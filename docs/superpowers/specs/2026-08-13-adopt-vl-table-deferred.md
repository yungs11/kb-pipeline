## D1. `adopt_vl_table` 규칙의 근거가 자기 도메인에서 0건이다

`_hybrid_scan_pages` 는 스캔 페이지를 전면 VL 로 교체할 때 **VL 이 낸 표를 버리고 paddle 표를
승계**한다(`adopt_vl_table = not keep`). 사용자가 "VL 이 GW 보다 표를 못 읽은 사례를 본 적
없다" 고 지적해 근거를 전수 확인했다.

| 확인 | 결과 |
|---|---|
| 규칙의 유일한 근거 | **R5 — 페이지 1장.** ABL p33 Re-TACRED 5행/42셀을 전면 VL 이 3번 다 놓침 |
| 그 페이지의 성격 | **네이티브 가로형 슬라이드**. 스캔이 아니다 |
| 그 실패의 실체 | 리더보드를 PAGE_HYBRID 의 "차트는 3줄 이내 요약" 조항이 삼킨 것으로 보인다 — **같은 페이지의 진짜 차트 3개는 정확히 요약**했다. **사용자 판단: VL 동작이 옳았다**(그 페이지에서 리더보드 표는 중요 콘텐츠가 아니다) |
| 규칙이 실제로 도는 곳 | `_hybrid_scan_pages` = **스캔 페이지**(`paddle_gw` 레인) |
| **스캔 페이지의 표 사례** | **0건.** `planA-measurements/layout/S_scan_*.json` 10장 전부 GW `<table>` 0개 — 표가 있는 세로형 스캔 페이지가 코퍼스에 **없다** |
| VL 의 표 실측(대조군) | LICO p10 **11행 45셀 + `rowspan`/`colspan` 3개 보존** · 정의서 p6 `<table>` 2개 깔끔 |
| **GW 의 표 실패 실측** | LICO p3 간트 → **`<td>` 1,098개 / 46,610자 거짓 표**(R4). VL 은 156자 요약 = 정상 |

**요약**: 자기 도메인(스캔)에서 한 번도 측정되지 않은 규칙이고, 표에 관해 실측된 **명백한
실패는 오히려 GW 쪽**이다. R11 도 같은 방향이다 — 9b 평가에서 "표·스캔전사는 **동등**,
ABL p33 표는 오히려 잡음" 이라 그 페이지가 유독 이상한 표본임을 시사한다.

## 왜 지금 제거하지 않나

1. **사용자 결정** — "처분은 우선 넘어가자"(2026-08-13). Phase 2a 범위 밖이다.
2. **`vl` 레인은 이미 사용자가 원하는 동작이다.** 표 승계가 없고 VL 산출물만 쓴다
   (`vl_elements_to_blocks(..., adopt_vl_table=True)`). 즉 **지금 당장 손해가 나는 경로가 아니다.**
3. **hybrid 는 계속 돈다** — V7-0(2026-08-13) 확인: 세로형 스캔 2장이 `OCR_NEEDED` 로 남아
   `paddle_gw` 레인에 간다. "사문이 되어 자동 정리" 될 거라던 가정은 **틀렸다.**
   그러므로 규칙도 계속 돌고, 처분은 **명시적 결정이 필요하다.**

## 언제 다시 봐야 하나

- **V7(hybrid 발화 실측) 직후** — 부동산교재 p7·p49 로 hybrid 를 실제로 태울 때
  그 페이지에 표가 있는지, VL 과 paddle 중 어느 쪽이 나은지가 **처음으로** 관측된다.
  지금은 표본이 없어 판단 자체가 불가능하다.
- **표가 있는 세로형 스캔 페이지를 코퍼스에 확보했을 때.** 그게 이 규칙의 유일한 검증 조건이다.
