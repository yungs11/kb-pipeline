## AI 에이전트 기반 온톨로지 자동 구축

### 1. 스미카 반자동 설계
**목표:** 원천 데이터의 의미 구조를 분석하여 OWL/RDFS 기반의 도메인 최적화 온톨로지 스키마 생성

**프로세스:**
1. **정보 분석 에이전트 (LUXIA3.5-Deep)** 가 '온톨로지 핵심 정보'를 분석한다.
2. 분석 결과는 '분석결과, 검색 쿼리'로 이어진다.
3. **정보 검색 에이전트 (A.RAG / LUXIA-Embedding)** 가 '내/외부 문서'를 검색하여 쿼리에 대응한다.
4. 검색된 '핵심정보+검색결과'는 '스키마 생성 에이전트 (LUXIA3.5-LLM)'로 전달된다.
5. 에이전트는 이를 바탕으로 '스키마 정보'를 생성한다.

### 2. 온톨로지 인스턴스 자동 추출
**목표:** 개체명 인식 (NER) 및 관계 추출 (RE) 기술로 대규모 텍스트/문서에서 의미 있는 트리플 (Subject-Predicate-Object) 을 정확하게 추출

**프로세스:**
1. **문서 파싱 에이전트 (Document Studio)** 가 '비정형 데이터'를 파싱하여 '구조화된 파싱 결과'를 생성한다.
2. **스키마 검색 에이전트 (LUXIA3.5-Deep)** 가 '파싱 결과, 스키마 정보'를 기반으로 검색을 수행한다.
3. **트리플 추출 에이전트 (LUXIA3.5-LLM)** 가 '온톨로지 정보'를 생성한다.

### 3. 자동화 정합성 검증
**목표:** SHACL 규칙 및 추론 엔진 기반으로 스키마 충돌, 트리플 오류, 누락된 관계를 AI 가 실시간 탐지하여 즉시 보정

**프로세스:**
1. **정보 통합 에이전트** 가 '온톨로지 정보'를 처리하여 중복 제거 및 지식 충돌을 수행한다.
2. **조건 분기:**
   - **False (충돌 발생 시):** '충돌 안내'로 이동하여 해결한다.
   - **True (정상 시):** 다음 단계로 넘어간다.
3. **정보 검증 에이전트 (LUXIA3.5-Deep)** 가 검증 작업을 수행한다.
4. **조건 분기:**
   - **False (검증 실패 시):** '충돌 안내'로 이동하여 해결한다.
   - **True (검증 성공 시):** 다음 단계로 넘어간다.
5. **적재 에이전트 (Knowledge Studio)** 가 최종적으로 온톨로지를 적재한다.

**기반:** Agent/Document/Knowledge Studio 기반
